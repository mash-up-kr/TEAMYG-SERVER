# 외부 서비스 생존 체크 런북 (#143)

서버 바깥의 무료 모니터링 서비스(**UptimeRobot**)로 서비스가 응답하는지 5분마다 확인하고, 이상이 있으면 Discord `💥uptime-robot` 채널로 알린다.
코드 변경은 없고, 가입과 설정은 사람이 직접 한다. 이 문서는 그 순서와 운영 방법을 정리한다.

## 배경

- 서버(EC2)의 메모리가 약 951MB라 Uptime Kuma 같은 상시 프로세스를 같은 서버에 둘 여유가 없다.
- 같은 서버에 감시 도구를 두면 서버가 죽었을 때 알림도 함께 사라진다. 외부 서비스는 서버가 죽어도 알림을 보낸다.

## 다른 알림과의 역할

| 알림 | Discord 채널 | 감시 위치 | 무엇을 아는가 |
|---|---|---|---|
| 서버 상태 알림 (`server-monitoring.md`, #142) | `#alerts`, `#server-report` | 서버 안 | CPU·메모리·디스크 과사용, OOM, 정기 리포트. 서버가 살아 있어야 보낼 수 있다 |
| **외부 생존 체크 (이 문서)** | **`💥uptime-robot`** | 서버 밖 | 서비스가 인터넷에서 응답하는지. 서버나 앱이 죽어도 알 수 있다 |
| 앱 에러 로그 | `#errors` | 앱 안 | 요청 처리 중 발생한 ERROR |

DB 포트는 RDS라 외부에서 접근할 수 없어 감시하지 않는다. 헬스체크가 DB 연결 상태를 반영하므로 DB 문제는 헬스체크 실패로 드러난다.

## 왜 UptimeRobot인가

2026-10-11에 각 서비스의 공식 요금·약관·통합 페이지를 확인한 결과다. 무료 플랜의 조건은 바뀔 수 있으니, 서비스를 다시 검토할 때는 공식 페이지를 다시 확인한다.

| 서비스 | Discord 알림(무료) | 약관 | 확인 간격 / 모니터 수 | 판단 |
|---|---|---|---|---|
| **UptimeRobot** | ✅ 무료 포함 (웹훅 URL 방식) | ✅ 상업 이용 포함 모든 용도 허용 (약관 3조, 2026-05 개정) | 5분 / 50개 | **채택** |
| HetrixTools | ✅ 무료 포함 | ⚠️ 상업 이용 언급 없음. 무료 계정은 오래 로그인하지 않으면 정지될 수 있음 | 1분 / 15개 | 1분 간격이 필요해지면 대안 |
| StatusCake | ⚠️ 무료에서 가능한지 미확인 | 제한 언급 없음 | 5분 / 10개 | 보류 |
| Better Stack | ❌ 무료는 Slack·이메일만 | 개인 프로젝트 대상 | - / 10개 | 제외 |

- UptimeRobot은 Discord와 약관이 모두 공식 페이지로 확인됐고, 약관과 공정 사용 정책에서 미로그인 정지 조항을 찾지 못했다. 5분 간격이면 서버 다운 감지에 충분하다.
- UptimeRobot 무료 플랜의 제약(공식 FAQ): "N회 실패 후 알림" 같은 지연 알림과 고급 HTTP 설정(정상 응답 코드 변경 등)은 Pro 전용이다. **키워드 모니터는 무료**다.
- Freshping은 2026-03-06에 서비스를 종료했다.

## 1. 사전 확인 (서버 밖에서)

대상 주소는 `https://api.parfait-app.store/actuator/health`이다.

```sh
# 헬스체크: 첫 줄 {"status":"UP"}, 둘째 줄 200 이어야 한다
curl -s -w '\n%{http_code}\n' https://api.parfait-app.store/actuator/health

```

- 헬스체크가 401/403/404면 모니터를 등록하기 전에 원인부터 해결한다 (Security 허용 경로, Caddy 프록시).
- 헬스체크 본문에 상세 정보(DB 종류, 디스크 용량 등)가 보이면 안 된다. prod는 숨기도록(`show-details: never`) 설정돼 있다.

## 2. 가입과 Discord 연동

1. **전용 Discord 채널·웹훅 만들기**: `💥uptime-robot` 채널 편집 → 연동 → 웹후크 → 새 웹후크, 이름 `uptimerobot`. 서버 알림을 받는 `#alerts`와 채널·웹훅을 분리해서, 외부 생존 알림만 따로 모아 보고 웹훅이 유출되면 이것만 폐기할 수 있게 한다. **웹후크 URL은 문서·메신저·이슈에 붙이지 않는다.**
2. **UptimeRobot 가입**: 팀 공용 계정으로 가입한다. 무료 플랜이고 카드 정보는 넣지 않는다.
3. **Discord 연동**: Integrations → Discord → 1번의 웹후크 URL 붙여넣기, 라벨 `discord-alerts`. 테스트 알림이 있으면 보내서 `💥uptime-robot` 도착을 확인한다.

화면 메뉴 이름은 바뀔 수 있다. 다르면 비슷한 기능을 찾아 진행한다.

## 3. 모니터 등록

헬스체크 모니터 **하나만** 등록한다. 헬스체크 요청은 DNS → TLS 인증서 → Caddy → 앱 → DB 연결을 모두 거치므로, 이 하나가 실패하면 그 경로 어딘가에 문제가 있다는 뜻이다. 루트(`/`) 모니터는 API 서버라 루트에 정상 페이지가 없고(무료 플랜은 정상 응답 코드를 바꿀 수 없어 오판 위험), 헬스체크와 같은 경로를 확인하는 것이라 만들지 않는다.

| 이름 | 유형 | URL | 조건 | 비고 |
|---|---|---|---|---|
| `parfait-health` | Keyword | `https://api.parfait-app.store/actuator/health` | 키워드 `"status":"UP"`이 **없으면** 알림 (Case sensitive) | 필수. 상태 코드만 보면 200인데 `DOWN`인 경우를 놓칠 수 있어 키워드로 본다 |

- 확인 간격: 5분 (무료 최소값)
- 알림 대상: `discord-alerts`
- 지연 알림 옵션은 무료에 없으니 기본값으로 둔다.
- SSL 만료 알림: HTTPS 모니터 설정에 SSL 확인이 보이면 켜 둔다. 무료에서 안 되면 넘어간다 (Caddy가 Let's Encrypt 인증서를 자동 갱신하므로 필수 아님). 결과를 "설정 기록"에 적는다.
- 상태 페이지는 만들지 않는다.

## 4. 장애·복구 알림 시험

운영 서비스는 건드리지 않고 **임시 모니터**로 확인한다.

1. 임시 모니터: 유형 Keyword, 이름 `test-down`, URL `https://api.parfait-app.store/actuator/health`, 키워드 `THIS_SHOULD_NOT_EXIST`, 조건 "키워드가 없으면 알림", 알림 대상 `discord-alerts`. 응답에 이 단어가 없으니 일부러 장애로 판정된다.
2. 5~10분 안에 `💥uptime-robot`에 **장애(Down) 알림**이 오는지 확인한다.
3. 임시 모니터의 키워드를 `"status":"UP"`으로 바꿔 저장하고, **복구(Up) 알림**이 오는지 확인한다.
4. 임시 모니터 `test-down`을 삭제한다.

실제 서버나 컨테이너를 내리는 시험은 하지 않는다. 외부에서 응답을 판정해 Discord로 보내는 경로는 위 시험으로 확인된다.

## 5. 운영

### 알림이 왔을 때 확인 순서
1. 브라우저나 `curl`로 직접 접속해 실제로 안 되는지 확인한다 (UptimeRobot 쪽 일시 장애일 수 있다).
2. 안 되면 서버에 접속해 `docker ps`로 `parfait`, `caddy` 컨테이너 상태를 본다.
3. 앱 로그를 본다: `docker logs --tail 100 parfait`.
4. `#alerts`에 같은 시각의 서버 알림(CPU·메모리·OOM, #142)이 있는지 본다. OOM이면 메모리 부족이 원인일 수 있다.
5. 서버 자체에 접속이 안 되면 EC2 콘솔에서 인스턴스 상태를 확인한다.

### 점검·배포로 일부러 서비스를 내릴 때
UptimeRobot에서 모니터를 **Pause** 했다가 끝나면 다시 켠다.

### 웹훅 폐기와 재발급
URL이 유출됐을 때는 Discord에서 `uptimerobot` 웹후크를 삭제하고 새로 만든 뒤, UptimeRobot의 Discord 연동 URL을 바꾼다.

### 서비스를 바꿀 때
새 서비스에 2~4단계를 마친 뒤에 UptimeRobot 모니터를 삭제하고 계정을 닫는다. 그 사이에 감시 공백이 없게 한다.

## 설정 기록

| 항목 | 내용 |
|---|---|
| 서비스 | UptimeRobot (무료 플랜, 카드 정보 없음 확인) |
| 공식 페이지 확인 날짜 | 2026-10-11 |
| 계정 소유자 | 팀 공용 계정 (teamYG). 개인 계정이 아니라 담당자가 바뀌어도 인수인계할 수 있다 |
| 확인 간격 | 5분 |
| 모니터 | `parfait-health` (Keyword `"status":"UP"`, 없으면 알림) 하나. UptimeRobot 화면 이름은 `api.parfait-app.store` |
| 알림 이벤트 | Discord 연락처에 Up events, Down events, SSL & Domain expiry 선택 (무료에서 선택 가능 확인, 2026-10-11) |
| Discord 채널·웹훅 | `💥uptime-robot` 채널의 `uptimerobot` 웹훅 (UptimeRobot 연동 라벨 `discord-alerts`) |
| 시험 완료 날짜 | 2026-10-11 (모니터 Up 확인, Discord 테스트 알림으로 장애·복구 메시지 수신 확인) |

## 한계

- 확인 간격이 5분이라 장애를 최대 5분 늦게 알게 된다.
- 무료 플랜에는 지연 알림이 없어서 아주 짧은 일시 장애에도 알림이 올 수 있다.
- 헬스체크가 `UP`이어도 특정 기능의 장애는 알 수 없다 (앱 에러 로그 `#errors`와 함께 본다).
- 무료 플랜의 조건과 약관은 바뀔 수 있다.
- UptimeRobot에 Discord 웹훅 URL이 저장된다. 그래서 전용 웹훅을 써서, 유출되면 그 웹훅만 폐기하면 되게 했다.
